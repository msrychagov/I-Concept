# Qwen3 1.7B на CPU внутри I-Concept

## Что изменено

- `.env.example`: пример переключён на `LOCAL_LLM_MODEL=qwen3:1.7b`. **Ваш реальный `.env` не меняется автоматически.**
- `docker-compose.cpu-ai.yml`: ограничивает Ollama одним параллельным запросом и одной моделью в памяти; отключает облачные возможности Ollama.
- `internal/platform/ollama/client.go`: HTTP-тайм-аут увеличен с 6 до 10 минут на запрос.
- `internal/usecase/ai_analysis.go`: тайм-аут всего отчёта увеличен с 6 до 20 минут.
- `docker-compose.yaml`: обновлены только комментарии с названием модели. Переменная модели и подключение к Ollama уже были реализованы.

Не изменены: структура и содержание тестов, расчёт баллов, база данных, API, интерфейс, роли и права пользователей.

## Установка на сервере с Docker Compose

Перейдите в папку, где лежит `docker-compose.yaml`.

1. Сохраните существующие `.env`, БД и секреты. **Не заменяйте** свой `.env` файлом `.env.example`. В существующем `.env` задайте:

   ```dotenv
   LOCAL_LLM_MODEL=qwen3:1.7b
   ```

   Переменная `DB_PASSWORD` и остальные параметры системы должны остаться без изменений.

2. Поднимите Ollama:

   ```sh
   docker compose -f docker-compose.yaml -f docker-compose.cpu-ai.yml --profile ai up -d ollama
   ```

3. Скачайте модель (около 1.4 GB на диске, Q4_K_M):

   ```sh
   docker compose -f docker-compose.yaml -f docker-compose.cpu-ai.yml exec ollama ollama pull qwen3:1.7b
   ```

4. Проверьте модель:

   ```sh
   docker compose -f docker-compose.yaml -f docker-compose.cpu-ai.yml exec ollama ollama list
   docker compose -f docker-compose.yaml -f docker-compose.cpu-ai.yml exec ollama ollama run qwen3:1.7b 'Напиши одно предложение на русском о роли обратной связи в обучении.'
   ```

5. Пересоберите приложение с увеличенными тайм-аутами:

   ```sh
   docker compose -f docker-compose.yaml -f docker-compose.cpu-ai.yml --profile ai up -d --build app
   ```

6. Откройте кабинет преподавателя → Диагностическое тестирование → Назначения и результаты → Результат конкретного студента → Сформировать ИИ-отчёт. В том же разделе можно сформировать отчёт по взводу. Для 1–2 совместимых завершённых тестирований формируется отчёт о полноте данных, но групповые баллы не раскрываются; для расчёта группового показателя необходимо минимум три индивидуальных результата.

## Диагностика

```sh
docker compose -f docker-compose.yaml -f docker-compose.cpu-ai.yml logs --tail=80 ollama
docker compose -f docker-compose.yaml -f docker-compose.cpu-ai.yml logs --tail=80 app
docker stats
free -h
```

- Если в кабинете написано «Локальная модель не подключена», проверьте переменную `LOCAL_LLM_MODEL` именно в корневом `.env` и пересоздайте `app`.
- Если модель отсутствует, повторите `ollama pull qwen3:1.7b` внутри контейнера `ollama`.
- `LOCAL_LLM_URL` уже равно `http://ollama:11434` в исходном compose; **внутри контейнера app не используйте `localhost`**.
- Если нет памяти для контекста 8192 токена, измерьте расход памяти и только после оценки длины входных данных меняйте `num_ctx` в `internal/platform/ollama/client.go`.
- 1.7B может ошибаться в содержании и структуре ответа; система отклоняет неполный JSON. Перед работой с реальными данными тестируйте обезличенные сессии.
- Ollama локальная, но прежний отдельный клиент GigaChat (для автобиографий) может оставаться включённым, если ключ задан.
- Исходный compose монтирует CA-сертификат из `../.secrets`; если его не было на сервере, настройте отсутствующий файл по штатной документации.

## Важные ограничения

Система рассчитывает показатели по заданной методике, а модель только формулирует предварительные педагогические пояснения. Тексты следует проверять преподавателю, не использовать для автоматического ранжирования, дисциплинарных санкций и выводов о психическом состоянии. Результаты сейчас кэшируются в RAM процесса и пропадут после перезапуска `app`.

Для сборки исходного проекта требуется Go 1.26, но на сервере с Docker можно использовать многоэтапный Dockerfile с Go 1.26 без установки Go на хост.
