# Локальный ИИ-анализ диагностического тестирования

Интеграция с **Ollama** и `qwen3:8b` работает без облачных API. Основные баллы вычисляет приложение по прежней методике; модель формулирует **предварительные педагогические пояснения**. Никакого дообучения на студентах не требуется.

## Запуск с Docker Compose

1. Убедитесь, что у приложения есть прежний `.env` с настройками PostgreSQL. В корневой `.env` проекта добавьте `LOCAL_LLM_MODEL=qwen3:8b` (для пробного старта с менее мощным сервером можно использовать `qwen3:4b`). **Не переносите реальные пароли в .env.example.**
2. Запустите Ollama: `docker compose --profile ai up -d ollama`.
3. Скачайте веса на машину один раз: `docker compose exec ollama ollama pull qwen3:8b`. Для `qwen3:8b` это примерно **5,2 ГБ** на диске, для `qwen3:14b` — около **9,3 ГБ**. Потребление оперативной памяти/VRAM выше и зависит от контекста и конфигурации.
4. Запустите приложение и его БД как обычно: `docker compose up -d --build app` (сервис миграций и БД будут запущены автоматически). Если приложение всё ещё использует существующий GigaChat, настройка CA-сертификата остаётся прежней. Для локальной модели GigaChat не нужен.
5. В преподавательском кабинете откройте **Диагностическое тестирование → Назначения и результаты**. Для студента нажмите **Результат**, затем **Сформировать ИИ-отчёт**. В разделе **ИИ-отчёт по взводу** выберите взвод и сформируйте сводку.

`LOCAL_LLM_MODEL` пустая — интеграция выключена. В Docker адрес Ollama для приложения: `LOCAL_LLM_URL=http://ollama:11434`. При запуске Go без Docker используйте `LOCAL_LLM_URL=http://127.0.0.1:11434` и `LOCAL_LLM_MODEL=qwen3:8b`. Docker не публикует API Ollama в сеть: порт доступен только с localhost сервера.

## API

API доступен **только преподавателю после входа в систему**:

- `GET /api/v1/sessions/{id}/ai-report` — текущий статус и готовый результат студента.
- `POST /api/v1/sessions/{id}/ai-report` — поставить формирование отчёта в очередь.
- `GET /api/v1/reports/ai/platoon?group=101` — статус и результат взвода.
- `POST /api/v1/reports/ai/platoon?group=101` — поставить сводку взвода в очередь.

Статусы: `off`, `idle`, `working`, `ready`, `failed`. Работа идёт в фоне, браузер опрашивает статус. Одна задача обрабатывается в каждый момент времени. JSON-схема задаёт желаемый формат генерации, но содержание и полнота полученного ответа не блокируют публикацию. Полные ответы сохраняются в `modelResponses`; даже при сбое последующего запроса уже полученный текст доступен в отчёте.

## Какие данные видит модель

Рассчитанные показатели передаются последовательно порциями до пяти: ID, название, компонент, балл и самооценки R/I/Z/N; для взвода также число участников. Определения и полнота данных остаются в серверной части отчёта. Для каждой порции модель возвращает интерпретации, учебные рекомендации и вопросы. Затем отдельный запрос формирует общий вывод и рекомендации на основе всех баллов и коротких фрагментов полученных интерпретаций. Тексты закрытых вопросов и отдельные выбранные ответы не отправляются. Для открытых вопросов текущего тестирования передаются вопрос и полный текст ответа из `Notes`, только если вопрос включён в сессию и отмечен как отвеченный. Открытые ответы обрабатываются отдельными порциями без обрезки исходного текста; итоговый запрос получает короткие фрагменты их обобщений. Ответы по автобиографии относятся к отдельному обработчику.

При старте приложение регистрирует через `/api/create` две конфигурации `i-concept-report:<hash>` на основе `LOCAL_LLM_MODEL`: общие инструкции для студента и взвода. Хеш зависит от базовой модели и текста инструкции. В последующих `/api/chat` передаются только данные текущего запроса; история других студентов не добавляется. Если регистрация недоступна, приложение отправляет системную инструкцию явно. Конфигурации используют существующие веса, но инструкция по-прежнему занимает контекст модели: это не дообучение и не гарантия однократного вычисления промпта. Одинаковый префикс может переиспользоваться кэшем Ollama; основной выигрыш достигается сокращением входных данных.

Для сводки берётся самая новая завершённая сессия каждого студента во взводе, затем наиболее многочисленная группа с одинаковой версией банка и шаблоном. Если совместимых завершённых тестирований меньше трёх, система формирует только структурированный отчёт о полноте данных — без групповых числовых значений. По каждому показателю групповой балл доступен лишь при наличии минимум трёх полностью рассчитанных индивидуальных оценок. Данные остальных студентов учитываются только в числе исключённых несопоставимых сессий.

Показатели D описывают восприятие условий, а не личностные качества. Балльная диагностика не устанавливает психологических диагнозов, политических взглядов, военной пригодности или реального поведения. Выводы модели требуют проверки преподавателем и не должны становиться основанием для автоматического наказания, отчисления или ранжирования.

## Ограничения первой версии

- Отчёты **кэшируются в оперативной памяти процесса**, привязаны к версии модели и содержимому показателей. При перезапуске приложения готовые тексты требуется создать заново; рассчитанные баллы и ответы при этом остаются в существующей БД.
- Скорость зависит от железа. Для 39 показателей модель вызывается отдельно для сводки и небольшими пакетами по десять показателей. Время может составлять несколько минут.
- Требуется проверка качества русскоязычных формулировок на реальных обезличенных примерах перед использованием в образовательной практике.
- Если одновременно включить прежний GigaChat и Ollama, **новый модуль диагностики использует только Ollama**; существующий обработчик автобиографии сохраняет старый настроенный провайдер.

В журнале приложения `AI report started` и `AI report ready` показывают начало, длительность всей генерации и количество полученных ответов модели.

## Тестирование

Нужен Go **1.26** (требование исходного проекта). Выполните `go test ./internal/platform/ollama ./internal/usecase ./internal/transport/http`, затем проверьте на локальном сервере корректность режима `off`, генерацию отчёта, контроль прав преподавателей и сводку взвода. На машине разработки с Go 1.23 эти тесты не запустятся без обновления Go. Для проверки интерфейса запустите `node --check` на изменённых JS-файлах.
