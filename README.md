# Я-концепция ВУЦ

Самостоятельная версия проекта на Go. Сервер, интерфейс, банк вопросов и схема модели собираются в один бинарный файл.
В Docker Compose рабочие данные хранятся в PostgreSQL. Банки вопросов и методика остаются в JSON.
Для локального запуска без настройки БД сохранён файловый режим; Node.js и Next.js не требуются.

## Быстрый запуск

Нужен Go 1.26 или новее.

```bash
go run ./cmd/vuc
```

Откройте `http://localhost:8080`. Вход и регистрация студента: `/student`, преподавателя: `/teacher`. Кабинет
преподавателя: `/research`. Регистрация закрыта: преподавателя приглашает администратор, студента — преподаватель. Почта
используется как логин.

Создать одноразовое приглашение преподавателю можно отдельной командой. Она обновит файл данных и завершится, поэтому
при локальном запуске выполняйте её до запуска сервера:

```bash
go run ./cmd/vuc -create-vuc 'ВУЦ при университете'
go run ./cmd/vuc -invite-teacher teacher@example.ru -vuc 'ВУЦ при университете'
```

Команда напечатает короткий код вида `ABCDE-FGHIJ`. Он действует 24 часа, привязан к указанной почте и используется один
раз. Преподаватель вводит код на странице `/teacher`. Создавать такие коды может только администратор.

ВУЦ создаёт только администратор отдельной командой или через `POST /api/v1/admin/vucs` с JSON
`{"name":"ВУЦ при университете"}` и Basic Auth. Справочник доступен администратору через `GET /api/v1/admin/vucs`.
Дубликаты названий с отличиями только в регистре или пробелах запрещены.

При выдаче кода и назначении преподавателя ВУЦ уже должен существовать в справочнике; произвольное название отклоняется.
Существование ВУЦ повторно проверяется при регистрации по приглашению. В профиле ВУЦ отображается без возможности
редактирования.

После обновления старые названия ВУЦ автоматически в справочник не добавляются. Администратор должен создать
соответствующие записи с прежними названиями; существующие привязки сохраняются. До этого новые регистрации и управление
взводами этих ВУЦ недоступны.

В разделе «Управление взводом» преподаватель видит взводы и студентов своего ВУЦ, создаёт и переименовывает взводы,
переводит студентов между ними, удаляет из состава и отключает или восстанавливает доступ к кабинету. Удаление из взвода
прекращает доступ к заданиям; отключение кабинета отзывает все сеансы и запрещает повторный вход. Учебные результаты
сохраняются. Доступ к диагностическим результатам остаётся ограниченным прежним владельцем-преподавателем.

Для приглашения выберите взвод и нажмите «Создать ссылку». Ссылка скрыта по умолчанию; доступны кнопки «Копировать
ссылку» и «Показать». Она действует 48 часов и подходит для нескольких студентов. ВУЦ и взвод назначаются сервером.
Новая ссылка для взвода отключает предыдущую, в том числе созданную другим преподавателем того же ВУЦ.

Для существующих преподавателей без ВУЦ администратор вызывает `PATCH /api/v1/admin/teachers/{id}/vuc` с JSON
`{"vuc":"ВУЦ при университете"}` и Basic Auth. При этом студенты преподавателя и их взводы привязываются к ВУЦ; старые
ссылки отзываются. До назначения ВУЦ управление взводами недоступно. Старые неиспользованные коды без ВУЦ нужно
перевыпустить.

Для работающего сервера администратор может создать приглашение через API, если настроены `VUC_ADMIN_USER` и
`VUC_ADMIN_PASSWORD`:

```bash
curl -u admin:SECRET -H 'Content-Type: application/json' \
  -d '{"name":"ВУЦ при университете"}' \
  http://localhost:8080/api/v1/admin/vucs

curl -u admin:SECRET -H 'Content-Type: application/json' \
  -d '{"email":"teacher@example.ru","vuc":"ВУЦ при университете"}' \
  http://localhost:8080/api/v1/admin/invitations/teachers
```

## Демонстрационные данные

Преподаватель: `teacher@example.test`, пароль `TeacherDemo2026!`.
Студенты: `student1@example.test` — `student9@example.test`, пароль для всех `StudentDemo2026!`.
Первый студент — Иванов Иван Иванович, взвод 101.

В демо три взвода (101–103), девять студентов, два шаблона и четыре назначения. Есть не начатые, частично заполненные и
завершённые тесты, а также закрытое назначение. Четвёртое назначение — автобиография взводу 101: у первого студента она
сдана, у второго начата (заполнено 4 раздела из 17), у третьего не начата. Для нового прохождения теста удобно войти как
первый студент, для автобиографии — как третий.

Повторное создание демо (при остановленном сервере):

```bash
go run ./cmd/vuc -demo-reset
```

Команда заменяет рабочие данные, предварительно сохраняя файл `data/vuc.json.backup-ДАТА`. Обычный запуск данные не
сбрасывает.

Без `DATABASE_URL` и `DB_HOST` данные сохраняются в `data/vuc.json`. Путь и адрес можно изменить:

```bash
go run ./cmd/vuc -addr 127.0.0.1:9000 -data ./private/vuc.json
```

Сборка и проверка:

```bash
go test ./...
go build -o vuc ./cmd/vuc
```

## Docker и PostgreSQL

```bash
cp .env.example .env
# Задайте свои DB_PASSWORD и VUC_ADMIN_PASSWORD в .env
docker compose up --build -d
```

Мигратор запускается перед приложением. Для переноса текущих данных в пустую БД:
`./scripts/import-data.sh ./data/vuc.json`. Для заполнения отдельной пустой демосреды:
`./scripts/seed-demo.sh`. Эти команды не запускаются автоматически.

Схема хранения, настройки, миграции, резервные копии и команды без Docker:
[работа с PostgreSQL](docs/database.md).

## Автобиография (фиксированные анкеты)

Поступающий заполняет электронную автобиографию вместо бумажного бланка. Это не тест:
ответы — текст, даты, списки, множественный выбор и повторяемые записи, поэтому анкеты
хранятся отдельно от сессий тестов (`Database.Submissions`). По сданной анкете программа
считает уровни потенциала и сводку по взводу. Языковой модели и текстового портрета пока нет.

Как пользоваться:

1. Преподаватель открывает пункт меню «Автобиография», назначает анкету всем взводам или
   одному (кнопка «Назначить тестирование»). «Посмотреть опросник» показывает разделы и
   вопросы без ответов. На «Главной» показана общая статистика обоих видов тестирования.
2. Студент видит в кабинете карточку в списке «Доступные тестирования», соглашается на сохранение
   сведений и проходит 17 разделов. Раздел начинается с вопроса-развилки; поля появляются
   только при нужном ответе. Раздел сохраняется при переходе «Далее» и при смене раздела,
   черновик не теряется при перезагрузке.
3. На последнем экране «Проверка и сдача» видны разделы с пропусками. Сдать можно, когда
   сохранены все разделы и заполнено всё обязательное, и поставлена галочка «Подтверждаю,
   что сведения верны». После сдачи анкета закрыта: студент видит только статус и дату,
   ответов не видит, исправить нельзя; в «Истории назначений» она значится как «Пройдено».
4. Преподаватель видит статус по каждому студенту (не начато / заполнено N из 17 / сдано),
   открывает «Анкету» — ответы по разделам с подписями вместо кодов, у несданной пометка
   «Не сдана». Доступ можно закрыть и возобновить, как у тестов.
5. У сданной анкеты над ответами — блок «Потенциал»: уровень по шести направлениям и из каких
   ответов он получился, строка с направлениями высокого уровня и государственные награды.
   Внизу страницы — «Потенциал по взводу»: по каждому направлению число студентов на каждом
   уровне; число открывает список студентов, имя — анкету с потенциалом.

Устройство:

- Описание анкеты — `internal/formbank/autobiography.json` (версия `1.0`), справочники (регионы, страны, языки, виды
  спорта, звания, виды и рода войск, национальности, экзамены,
  сферы, факультеты ВШЭ) — `internal/formbank/refs/*.json`. Всё встроено в бинарник.
  При старте описание проверяется (`formbank.Validate`): уникальные идентификаторы, развилки
  ссылаются на более раннее поле и существующий вариант, списки есть и не пусты.
- Типы полей: `choice`, `multi`, `text`, `textarea`, `date`, `month`, `year`, `group`
  (повторяемые записи без вложенных групп). `showIf {field, in}` — поле видно, только если
  значение управляющего поля входит в `in`; поле ищется сначала в той же записи, затем в
  разделе. Скрытое поле не показывается, не требуется, его значение отбрасывается при
  сохранении. `required` действует только на видимое поле; у группы `min` — число записей.
  `suggest: true` — текстовое поле с подсказками из ответов других студентов (название
  школы, населённый пункт школы, район военкомата, направление подготовки в ВШЭ).
  `llm: true` — поле уходит языковой модели (см. «Сведения для модели» ниже); остальные
  поля не уходят никогда.
- Формат ответов: `choice` — строка (id варианта), `multi` — массив строк, `text`/`textarea` —
  строка, `date`/`month`/`year` — `ГГГГ-ММ-ДД` / `ГГГГ-ММ` / `ГГГГ`, `group` — массив объектов.
  Сохранение раздела заменяет ответы только этого раздела; черновик может быть неполным.
- Обязательность: разделы 1–11 — всё с учётом развилок; разделы 12–16 — развилка «да / нет»,
  а при «да» хотя бы одна запись (спорт, творчество; у записи обязателен вид спорта или
  направление) или хотя бы один отмеченный пункт (военно-патриотическое, наука,
  волонтёрство); раздел 17 необязателен и считается заполненным после «Далее». Дата не может
  быть позже сегодняшней по московскому времени.
- Списки: у учебного заведения в списке регионов есть пункт «За пределами России»
  (`refs/school_regions.json` = `regions.json` плюс этот пункт; в остальных полях используется
  `regions`). В языках есть «Другой язык» с полем «Название языка». Студенту описание
  анкеты отдаётся без пометок `llm`.
- Маршруты: студент — `GET /students/me/submissions/{id}`, `PUT …/consent`,
  `PUT …/sections/{sectionId}`, `POST …/completion`, `GET …/suggestions?field=&q=`;
  преподаватель — `GET /forms/{formId}`, `GET /forms/{formId}/overview`,
  `GET /submissions/{id}`. Назначение — `POST /assignments` с `formId` вместо `profileId`
  (шаблон не нужен), закрытие доступа — `PATCH /assignments/{id}`. Страница студента —
  `/autobiography?id=…`. Проверка сдачи без пропусков возвращает `422` с `sections` и `missing`.
- Потенциал — `internal/usecase/potential.go`, правила по шкале из
  `Вики/Автобиография/Шкала потенциала.md`. Уровни: `high`, `medium`, `initial`, `none`
  (высокий, средний, начальный, не выражен); общего уровня нет. Считается только по сданной
  анкете, при каждом запросе заново из ответов: в базе не хранится, одинаковые ответы дают
  одинаковые уровни. Свободный текст и государственные награды на уровни не влияют.
  «До года» включает разовое участие. Сводка по взводу берёт последнюю сданную анкету каждого
  студента. Маршруты: `potential` в ответе `GET /submissions/{id}`,
  `GET /forms/autobiography/potential?platoon=`.
- Сведения для модели — `internal/usecase/model_input.go`: по сданной анкете собирается
  обезличенный JSON (`submissionPayload`), не зависящий от модели. Поля идут
  в порядке анкеты, «уровни» — в порядке шкалы. Уходят только поля с `llm: true`; коды
  вариантов заменены текстом, который видел студент; отмеченные пункты идут в порядке анкеты,
  вариант «другое» заменяется введённым текстом. Свободный текст в полях с `llm: true`
  уходит так, как его написал студент. Из остальных полей программа считает только возраст
  (по дате рождения на московскую дату сдачи, чтобы сведения не менялись после дня рождения)
  и число детей. По собственной уголовной ответственности уходит только «привлекался» или
  «не привлекался». Отпечаток — sha256 от JSON в порядке анкеты, без пробелов и
  экранирования (`payloadFingerprint`): по нему будет храниться портрет, одинаковые
  обезличенные ответы дают один отпечаток. Вывод по этим сведениям — см. «Выводы языковой модели» ниже.
- Анкеты сравнения моделей (`Вики/Автобиография/Сравнение моделей/анкеты/`) генерирует
  программа из ответов `comparisonAnswers` в `model_input_test.go`:
  `go test ./internal/usecase -run TestComparisonQuestionnaires -update` перезаписывает
  `internal/usecase/testdata/model_input/`, затем файлы копируются в Вики. Тест следит, чтобы
  копии совпадали (если Вики лежит рядом с проектом). Ещё тесты проверяют, что каждое поле с
  `llm: true` попадает в модель, другие поля не попадают, а все ключи разрешены списком
  `ALLOWED` в `compare.py` (его копия — в тесте, менять вместе).
- Новая фиксированная анкета добавляется новым JSON-файлом в `internal/formbank/`.

### Выводы языковой модели

Сданная автобиография сама уходит в языковую модель (GigaChat), преподаватель открывает готовый
вывод в окне «Анкета»: краткая характеристика, потенциал с текстом по шести направлениям,
«что можно использовать», «что учесть» и подпись «Составлено автоматически по сведениям, которые
сообщил студент» с датой, без названия модели. Уровни на экране всегда те, что посчитала
программа; уровень из ответа модели только проверяется. Слой общий: автобиография — первая задача на
нём, к нему подключаются и другие тесты.

- Модель включается настройками окружения; без `GIGACHAT_AUTH_KEY` и `GIGACHAT_MODEL` она выключена,
  анкеты работают как раньше, у преподавателя — «Языковая модель не подключена». Остальные настройки:
  `GIGACHAT_SCOPE` (по умолчанию `GIGACHAT_API_PERS`), `GIGACHAT_CA_FILE` (корневой сертификат
  Минцифры, добавляется к системным), `GIGACHAT_OAUTH_URL` и `GIGACHAT_API_URL` для тестов. Ключ и сертификат
  лежат в `.secrets/` в корне рабочей папки, не в `project/`: `docker-compose.yaml` читает `../.secrets/llm.env`
  и монтирует сертификат. Если файла сертификата нет, Docker создаёт на его месте папку, модель не
  включится, а в журнале будет «certificate file». Модель — настройка, а не код: её выбор ждёт решения
  руководителя.
- Порт `usecase.TextModel` (`llm.go`), клиент `internal/platform/gigachat` на `net/http`
  (токен на 30 минут обновляется за минуту до конца; ошибки без ключа и токена).
- Инструкции и схемы ответа — `internal/promptbank/<задача>/<версия>/`. Действующая — `autobiography/v2`
  (20 октября): от `v1` отличается только абзацем про «что учесть» — каждый пункт только факт, без
  выводов, с примерами и точной фразой про уголовную ответственность. Правка текста — новая папка `vN`,
  прежние не меняются; программа берёт у задачи самую новую версию (`promptbank.Latest`: число после `v`,
  `v10` новее `v2`), а тест сверяет её с `Вики/Автобиография/Сравнение моделей/Инструкция.md`.
- Составление — `portraits.go`: один фоновый обработчик, вызовы по одному. Портрет составляется
  сразу после сдачи, при старте программы докладываются недостающие (в том числе после смены версии
  инструкции или модели). Перед отправкой общая для всех задач очистка: в любом текстовом значении
  полная дата, отчество, почта и телефон заменяются на `[скрыто]`, остальной текст уходит как есть
  (имя и фамилия без отчества не распознаются; поэтому под «Достижениями», курсами и своими увлечениями
  студент видит подсказку «Без имён и фамилий.»). Ключ, отпечаток и сохранённый `Input` считаются уже от
  очищенных сведений, поэтому анкеты, различающиеся только вырезанным куском, дают один портрет. Значение
  неизвестного вида в сведениях очистка не пропускает: сведения не отправляются. До трёх попыток, пока ответ
  не пройдёт проверку задачи (`portrait_tasks.go`: схема, шесть направлений по порядку, уровни как у
  программы, не больше пяти пунктов; в «что учесть» нет слов вывода — «влия», «учитыв», «при
  планировании», «рекоменд» и т. п., а при уголовной ответственности есть «подробности — в ответах
  студента»; список слов — `consequence`, его копия — в `compare.py`). Замечания проверки называют пункт
  по номеру и текст ответа не цитируют. Не получилось — у преподавателя кнопка «Повторить».
- Уже составленный портрет показывается всегда: если модель отключена или сменена (другая модель, новая
  версия инструкции), преподаватель видит последний портрет на те же обезличенные сведения, а новая модель
  или версия составляет свой в фоне, и со следующего открытия показывается он. «Не подключена» и «не
  удалось» видны только там, где портрета ещё нет.
- Портрет хранится в таблице `portraits` (миграция `002`) под ключом sha256 от задачи, версии
  инструкции, модели и обезличенных сведений. Студента и анкеты в записи нет: одинаковые сведения
  двух студентов дают одну запись, повторно модель не вызывается. Старые версии остаются. В записи
  лежит и то, что именно ушло в модель.
- В журнал пишутся задача, первые 12 знаков ключа, статус, секунды, токены, число вырезанных кусков и
  причина сбоя (текст ошибки клиента или список замечаний проверки, до 300 знаков); сведения и текст
  ответа — нет.
- Маршруты: `GET /api/v1/portraits/{task}/{sourceId}` (статус и текст), `POST` там же — «Повторить».
  Только для преподавателя своего назначения, иначе 404.
- Новая задача: папка в `promptbank`, сборщик обезличенных сведений, проверка ответа, доступ преподавателя,
  отрисовка в `window.portraitRenderers[задача]` и вызов `queuePortraits` там, где источник завершается.

Анкета содержит судимости и сведения о родственниках. Регистрация преподавателей уже закрыта, но
чувствительные поля не шифруются, а портреты не удаляются вместе со студентом. До решения по этим
пунктам вводить данные настоящих студентов нельзя.

## Хранение и безопасность

В версии `pilot-2.2` в «Я концепцию» включён отдельный раздел «Мое самочувстсвие»:
149 вопросов и 28 описательных показателей из предоставленных материалов, без блока о военнослужащем будущего.
В новых полных шаблонах раздел включён. Состав регулируется через показатели и вопросы шаблона.
При назначении сохраняется выборка до двух вопросов на описательное направление. Психологические ответы не входят в педагогические баллы.
Состав, учёт отказов и неприменимости, сохранение старых версий и границы реализации описаны в
[документации раздела](docs/psychological-module.md).

В разделе «Диагностическое тестирование» доступны вкладки «Назначения и результаты» и «Шаблоны тестирования».
Назначение «Я концепции» выполняется только в этом разделе, автобиографии — в разделе «Автобиография».
На главной странице остаются карточки показателей и инфографика прохождения обоих видов тестирования:
кольцевые диаграммы общей статистики и полосы прогресса по взводам. Доступны фильтры взвода и активных назначений.
Статистика считает пары «студент — назначение» и различает завершённые, начатые и не начатые тестирования.

В редакторе шаблонов доступны вкладки «Вопросы» и «Показатели». Исключайте показатели флажками, находите вопросы поиском
и фильтрами, меняйте формулировку, раздел и варианты ответа в окне редактирования. Новые вопросы используют шкалу 1–5 и
включаются в среднее выбранного показателя. Удаление вопроса можно отменить до следующего удаления. Кнопка «Сохранить
шаблон» применяет весь набор изменений. Существующие сессии сохраняют собственную копию вопросов; обновлённый шаблон
применяется к новым ссылкам. Раздел вопроса определяет его расположение; основной или дополнительный модуль и тип ответа
существующего вопроса сохраняются.

- Назначения создаются одному взводу или всем взводам. Они доступны также студентам, зарегистрировавшимся позднее.
  Состав вопросов фиксируется в момент назначения.
- Студент видит только свои назначения; для завершённых тестов — название, статус и дату, без расчёта показателей и
  исходных ответов.
- Преподаватель управляет назначениями и просматривает результаты в разделе соответствующего вида тестирования.
  Главная страница показывает статистику прохождения обоих видов по взводам.
- Пароли хранятся как PBKDF2-SHA256 (600000 итераций) с индивидуальной солью; сеансы входа действуют 24 часа, cookie —
  HttpOnly и SameSite.
- Изменения анкеты используют номер ревизии и не позволяют незаметно перезаписать ответ из другого окна.
- Файл данных записывается через временный файл и атомарное переименование.
- Преподаватель регистрируется по одноразовому коду администратора. В файле хранится SHA-256-хеш кода, код привязан к
  почте и истекает через 24 часа.
- Студенты регистрируются по ссылке преподавателя, привязанной к одному взводу. Ссылка действует 48 часов и может
  использоваться несколькими студентами; в файле хранится только хеш её ключа.
- Студенты, шаблоны, назначения, сессии и анкеты изолированы по преподавателю. Подмена ID чужой записи возвращает ошибку
  и не раскрывает данные.
- При первом запуске после обновления старая база автоматически закрепляется за преподавателем, если он в ней один. Если
  старых преподавателей несколько, неоднозначные записи блокируются: назначить владельца нужно вручную из резервной
  копии перед рабочим использованием.
- Basic Auth используется только административным маршрутом создания приглашений преподавателям. Доступ к
  преподавательским данным требует cookie конкретного преподавателя.
- Для размещения в интернете используйте HTTPS.
- Регулярно создавайте резервные копии PostgreSQL через `pg_dump` (в файловом режиме — `data/vuc.json`).

Все необходимые веб-ресурсы, банк вопросов и схема модели встроены в собираемый бинарный файл.

## Архитектура проекта

```text
cmd/vuc/                         точка входа, параметры запуска
internal/
  app/                           сборка зависимостей приложения
  domain/model/                  аккаунты, вопросы, шаблоны, сессии, назначения
  usecase/                       сценарии использования и расчёты
    llm.go, portraits.go         порт языковой модели, очередь и хранение выводов
    portrait_tasks.go            задача «автобиография»: проверка ответа, доступ
    repository.go                интерфейс хранилища
    accounts.go                  регистрация, вход, личный кабинет
    teacher_settings.go          профиль и пароль преподавателя
    assignments.go               назначения тестирований
    survey.go                    ответы, согласие, завершение
    forms.go, form_rules.go      фиксированные анкеты: сохранение разделов, проверка, прогресс
    form_suggestions.go          подсказки для текстовых полей
    forms_teacher.go             описание, обзор и ответы анкет для преподавателя
    research.go                  управление шаблонами и сессиями
    assessment.go                расчёт показателей
    reports.go                   группировка и представление результатов
  repository/jsonfile/           локальное хранилище в JSON
  repository/postgres/           PostgreSQL: организации, аккаунты, учебные данные
  platform/database/             настройка пула pgx
  migrations/sql/                версионированные SQL-миграции
  transport/http/                маршруты, HTTP, cookie, авторизация, статика
  questionbank/                  встроенный банк вопросов
  formbank/                      встроенные описания фиксированных анкет и справочники
  promptbank/                    встроенные инструкции и схемы ответа языковой модели
  platform/gigachat/             клиент GigaChat
web/
  pages/                         HTML-страницы
  static/
    css/                         общие стили и стили редактора
    js/shared/                   авторизация, загрузчик, пагинация
    js/teacher/                  экраны кабинета преподавателя
    js/student/                  прохождение теста и заполнение автобиографии
    images/                      логотип и схема модели
  embed.go                       встраивание фронтенда в Go-бинарник
```

Зависимости направлены к внутренним слоям: `transport/http → usecase → domain/model`.
Сценарии используют интерфейс `usecase.Repository`; адаптер `repository/postgres` или
`repository/jsonfile` подключается в `internal/app`. В сценариях нет зависимостей от HTTP или файловой системы.
HTTP-слой преобразует запросы в команды и ошибки приложения в коды ответа.

Хранилище выполняет изменения транзакционно. PostgreSQL сохраняет изменённые строки
в одной транзакции; файловый адаптер записывает копию через временный файл и атомарное
переименование. Ошибка сценария или записи не изменяет текущие данные.
Для совместимости сохранены JSON-поля базы и параметры запуска.
В файловом режиме миграция JSON не требуется. Перенос в PostgreSQL выполняется явно
командой `importdata`; подробности в [документации БД](docs/database.md).

Банк вопросов хранится отдельно от публичной статики. Фронтенд доступен по путям
`/assets/css/`, `/assets/js/` и `/assets/images/`. HTML, JavaScript, CSS, изображения
и банк по-прежнему встраиваются в один исполняемый файл. Docker-сборка копирует
обе директории: `internal` и `web`.

Новый сценарий добавляйте в `internal/usecase`, HTTP-адаптер — в `internal/transport/http`.
Правила расчёта и проверки данных не должны зависеть от обработчиков HTTP.
Для другого способа хранения реализуйте `usecase.Repository` и подключите его в `app.New`.
Тесты расположены рядом с проверяемыми слоями; общая команда запуска — `go test ./...`.

## HTTP API и Swagger

- Swagger UI: `http://localhost:8080/swagger/`.
- OpenAPI 3.0.3: `http://localhost:8080/api/v1/openapi.json`.
- Файл спецификации: `web/static/openapi.json`.
- Обновление спецификации: `python3 scripts/generate_openapi.py`.

API использует отдельные маршруты с префиксом `/api/v1` и HTTP-методы:

| Операция                                        | Метод и путь                                                                                  |
|-------------------------------------------------|-----------------------------------------------------------------------------------------------|
| Вход преподавателя                              | `POST /api/v1/auth/teacher/login`                                                             |
| Приглашение преподавателя                       | `POST /api/v1/admin/invitations/teachers`                                                     |
| Ссылка для студентов взвода                     | `POST /api/v1/teachers/me/student-registration-links`                                         |
| Регистрация по приглашению                      | `POST /api/v1/auth/{role}/register`                                                           |
| Изменение профиля                               | `PATCH /api/v1/teachers/me`                                                                   |
| Смена пароля                                    | `PUT /api/v1/teachers/me/password`                                                            |
| Шаблоны                                         | `GET /api/v1/templates`, `POST /api/v1/templates`                                             |
| Сохранение шаблона                              | `PUT /api/v1/templates/{id}`                                                                  |
| Назначение                                      | `POST /api/v1/assignments`                                                                    |
| Открытие / закрытие доступа                     | `PATCH /api/v1/assignments/{id}`                                                              |
| Начало / продолжение                            | `POST /api/v1/students/me/assignments/{id}/session`                                           |
| Сохранение ответа                               | `PUT /api/v1/students/me/sessions/{id}/answers/{itemId}`                                      |
| Завершение                                      | `POST /api/v1/students/me/sessions/{id}/completion`                                           |
| Отчёт                                           | `GET /api/v1/sessions/{id}/report`                                                            |
| Автобиография: открыть, сохранить раздел, сдать | `GET /api/v1/students/me/submissions/{id}`, `PUT …/sections/{sectionId}`, `POST …/completion` |
| Автобиография: обзор и ответы                   | `GET /api/v1/forms/{formId}/overview`, `GET /api/v1/submissions/{id}`                         |
| Автобиография: потенциал по взводу              | `GET /api/v1/forms/{formId}/potential?platoon=`                                               |
| Вывод языковой модели: показать / повторить     | `GET /api/v1/portraits/{task}/{sourceId}`, `POST` там же                                      |

Поле `op` больше не используется. Старые `/api/vuc`, `/api/account`, `/api/teacher`
удалены; внешние клиенты нужно перевести на новые маршруты. Фронтенд уже обновлён.
Тело шаблона передаётся непосредственно, без оболочки `profile`; ID берётся из URL.
JSON-запросы требуют `Content-Type: application/json`. Неизвестные поля отклоняются.
Создание аккаунта, шаблона, назначения и импорт возвращают `201`; остальные успешные
операции — `200`. Неподдерживаемый HTTP-метод возвращает `405` с заголовком `Allow`.

Для вызовов из Swagger выполните вход через `Try it out` в маршруте авторизации:
браузер сохранит HttpOnly cookie и будет отправлять её автоматически. Студент и
преподаватель используют отдельные cookie. Swagger UI 5.33.1 встроен локально,
без CDN и внешнего валидатора. Источник и лицензия находятся в
`web/static/vendor/swagger-ui/`.
